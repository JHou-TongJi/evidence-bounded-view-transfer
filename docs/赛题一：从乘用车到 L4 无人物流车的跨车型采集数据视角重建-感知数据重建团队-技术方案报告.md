# 赛题一技术方案报告：乘用车道路数据到 L4 小车 7V 视角重建

**团队名称：**感知数据重建团队
**团队成员：**钟睿智 ，陈斯蕾

## 1. 任务定义与交付范围

给定 NCore V4 乘用车道路 clip 的多相机图像、标定、车辆轨迹和辅助 LiDAR/目标轨迹，本项目生成一个虚拟 L4 低速无人配送车在同一 NCore world 坐标系、同一参考时间上的 7V 视觉序列。

本项目的固定输入样例为 Ncore clip `7fd4d554-b155-45c6-a46a-646486029d85` 的 chunk 0。输出为 7 路 RGB：每路 1920×1080、299 帧、30 FPS，序列持续 9.9667 秒。交付七条 MP4、一个同步 7V mosaic 与具有代表性的帧。

## 2. 输入数据与坐标关系

输入是 NCore V4 的原始道路采集：7 路 FTheta 相机的 RGB、每帧曝光起止时间、相机安装外参、rig 在世界坐标中的 pose、`lidar_top_360fov` 稀疏 LiDAR，以及 cuboid track 和保守动态实例 mask。源相机是畸变 FTheta，并可能有 rolling shutter；目标小车输出则是工程定义的校正 pinhole/global-shutter midpoint proxy。

NCore 使用 `T_source_target` 命名：它把 source 坐标点变换至 target 坐标。对目标相机有：

```text
p_rig   = T_camera_rig · p_camera
p_world = T_rig_world(t) · p_rig
T_camera_world(t) = T_rig_world(t) · T_camera_rig
```

渲染器再取逆矩阵得到 OpenCV world-to-camera view matrix。虚拟 L4 小车沿用源采集车在各时刻的行驶轨迹与世界定位；在同一条轨迹上，将原乘用车的传感器布局替换为目标小车的 7V 相机布局。因此，道路场景仍位于同一世界坐标系，变化的是相机相对车体的安装位置、朝向和成像参数。

## 3. 主重建与生成流程

```text
NCore 7V RGB / pose / LiDAR / mask
  ├─ FTheta → 20 tile virtual-pinhole proxy
  ├─ 静态 2D Gaussian Splatting（5 相机、完整 299 帧）
  │    └─ 道路 LiDAR 深度监督 + 保守动态 mask 排除 RGB 监督
  ├─ 7 相机多时刻天空语义融合 → world-direction temporal cubemap
  ├─ 来源相机时间留出通过的刚性 2DGS actor expert registry
  └─ 目标 L4 7V 直接 1920×1080 surfel rasterization
       ├─ 静态 2DGS RGB
       ├─ alpha 后方采样 temporal sky
       └─ 仅在视角/距离/时间门控通过时叠加一个 actor expert
```

### 3.1 静态背景：surface-aligned 2DGS

最终静态背景模型为 5 路上下文、20 个 virtual-pinhole tile、480×270 proxy 训练输入、12,000 iteration 的官方  [**2D Gaussian Splatting 模型**](https://github.com/hbb1/2d-gaussian-splatting) 。2DGS 将 Gaussian 限制为局部表面盘而非自由体积 splat，用于减轻普通 3DGS 在道路、路沿、树线、建筑边缘出现的厚片、拉丝和远景漂浮。

模型训练期间，以 source-priority 动态实例 mask 排除**动态目标** RGB 监督；道路区域使用**真实 LiDAR 深度**作为物理尺度约束。单目深度估计模型 [Depth Anything V2](https://github.com/DepthAnything/Depth-Anything-V2) 经 LiDAR 尺度标定后，为道路区域提供低权重深度先验，并与真实 LiDAR 监督共同约束静态表面。最终 1080p 图像由训练完成的 2DGS 模型依据目标 pinhole 相机参数直接光栅化生成，可提升采样密度并缓和边缘锯齿；动态目标和未被充分观测的高频几何仍受原始训练观测限制。

### 3.2 天空：世界方向 temporal cubemap

使用 7 路源相机、chunk 内 18 个时间采样和本地 SegFormer sky mask 构建世界坐标 cubemap。渲染时，根据目标像素的世界方向采样同时间天空，合成公式为：

$$
\Large C_{final} = C_{2DGS} + (1 - α_{2DGS}) · C_{sky}
$$

天空只填充 2DGS 未覆盖的背景；不修改 2DGS 的 alpha、道路表面或 actor 几何。cubemap 无效方向回退为黑色，因此其覆盖与接缝仍作为已知风险记录。

### 3.3 动态刚性对象：camera-gated actor expert

对车辆/作业设备不强行做完整新视角生成。每个候选 actor 先在来源相机的时间留出帧上评价 masked RGB MAE、alpha IoU 和面积比；只有达标的 6 个 expert 被放入 registry。目标视角中，对同一 actor 仅选取一个满足以下条件的 expert：观察方向夹角不大于 25°、到相机距离比在 0.60–1.60、时间落入其来源观测窗，并在前后 100 ms 淡入/淡出。其余时刻严格回退静态背景。

该 fail-closed 策略的目的，是避免把单目或跨视角不可靠的 actor 叠加成重影。actor 之间按局部 surface depth 排序；不使用静态背景 expected depth 作硬遮挡真值，因为静态背景本身可能已烘焙动态目标，硬 gate 已被实验证明会造成灰洞。

## 4. 目标 L4 小车与 7V 相机定义

目标车型设定为 **L4 低速无人配送车**，其车身尺寸、载荷能力与应用场景参考了 [Neolix X3 公开产品资料](https://www.neolix.cn/productTechnology)。本项目据此构建了尺寸级和传感器布局均适用于园区、校园、住宅区及末端配送道路的工程化目标车辆模型；相机内外参为面向重建实验定义的虚拟标定参数。车辆假设长 2.69 m、宽 1.08 m、高 1.82 m、轴距 1.73 m、载荷 520 kg、货厢 3.0 m³，适用于园区、校园、住宅区和城市末端配送道路。

目标 ego 坐标为右手系：`+x` 向前、`+y` 向左、`+z` 向上；原点是后轴中点的地面投影。相机采用 OpenCV 坐标：`+x` 向右、`+y` 向下、`+z` 向前。每台相机均为 rectified pinhole，输出 1920×1080、30 FPS，水平 FOV 100°，垂直 FOV 67.673°，内参为 `fx=fy=805.5356 px, cx=959.5 px, cy=539.5 px`。

## 5. 结果解释与适用边界

静态背景、世界方向天空和连续 target pose 是本次结果的主要可信成分。刚性 actor expert 只能表示“在来源视图中验证过、并且与目标视角门控兼容的局部动态增强”。行人、未通过留出验收的车辆、背面和被遮挡表面不会生成可信几何；它们可能表现为静态背景中的残留、模糊或缺失。

本项目可作为跨车型 7V 相机布局设计、静态道路环境重建、连续新视角生成与保守动态目标增强的工程验证样例。对于动态目标的完整性、遮挡关系及传感器级真实性，仍建议结合目标车型实采数据或更严格的跨视角验证进一步评估。
