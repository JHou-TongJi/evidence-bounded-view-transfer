| 数据格式版本       | NCore V4                                                     |

## 2. 本项目使用的数据规模

本项目明确区分原始观测、训练/构建输入、验证输入与最终展示输出，避免将它们混为同一类数据。

| 数据类别          | 规模                                                         | 用途                                               |
| ----------------- | ------------------------------------------------------------ | -------------------------------------------------- |
| 原始 NCore 场景   | 1 个 clip、1 个 chunk                                        | 本次 final 的唯一源场景                            |
| 源 RGB 相机       | 7 路相机、每路 299 个参考时刻                                | 静态场景训练、天空构建、动态实例监督、来源视图评估 |
| 顶置 LiDAR        | 199 个 `lidar_top_360fov` sweep                              | 道路尺度约束、深度 holdout、动态对象可观测性审计   |
| 静态场景上下文    | 5 路物理源相机、20 个 virtual-pinhole tile 方向、299 个时间参考 | 训练最终静态 2DGS 背景                             |
| 天空观测          | 7 路相机 × 18 个 chunk 时间采样                              | 构建 world-direction temporal sky cubemap          |
| 刚性 actor expert | 6 个通过来源相机时间留出门槛的 expert，覆盖 track 17/18/42/67 | 对目标视角实施保守动态增强                         |
| 最终目标输出      | 7 路目标相机 × 299 帧 = 2,093 帧                             | 1920×1080、30 FPS、9.9667 秒 L4 7V demo            |
| 最终提交媒体      | 7 条单路 MP4、1 条同步 7V mosaic、10 张代表帧                | 展示与评审；不复制完整 RGB PNG 序列                |

最终视频由已经生成的 2,093 张目标视角 RGB 渲染帧编码得到，但提交包只保留 MP4 和代表帧，以控制体积并降低对派生图像的重复分发范围。

## 3. NCore V4 数据结构

每个 NCore clip 由一个 sequence JSON 和多个传感器存储包组成。数据集卡中给出的典型结构如下：

```
clips/<clip_uuid>/
├── pai_<clip_uuid>.json
├── pai_<clip_uuid>.ncore4.zarr.itar
├── pai_<clip_uuid>.ncore4-camera_cross_left_120fov.zarr.itar
├── pai_<clip_uuid>.ncore4-camera_cross_right_120fov.zarr.itar
├── pai_<clip_uuid>.ncore4-camera_front_tele_30fov.zarr.itar
├── pai_<clip_uuid>.ncore4-camera_front_wide_120fov.zarr.itar
├── pai_<clip_uuid>.ncore4-camera_rear_left_70fov.zarr.itar
├── pai_<clip_uuid>.ncore4-camera_rear_right_70fov.zarr.itar
├── pai_<clip_uuid>.ncore4-camera_rear_tele_30fov.zarr.itar
└── pai_<clip_uuid>.ncore4-lidar_top_360fov.zarr.itar
```

### 3.1 Sequence JSON

`pai_<clip_uuid>.json` 是数据入口文件，声明传感器 component store、时间范围、坐标变换图和数据模式。项目通过该文件定位相机图像、LiDAR、离线标定、ego pose 与 cuboid track。

### 3.2 相机数据与标定

每路相机存储包含：

- RGB 图像帧；
- 帧曝光起止时间戳；
- 相机内参，包括 FTheta 畸变模型、多项式参数、主点、最大视场与线性校正项；
- 相机相对 rig 的安装外参 `T_sensor_rig`；
- 相机有效区域/ego mask 等辅助信息；
- rolling-shutter 扫描方向信息。

源相机使用 FTheta 模型，部分相机存在 rolling shutter。因此，原始图像不能直接等同于 pinhole 投影；项目在读取原始观测、构建天空及进行几何审计时保留 NCore 原始相机模型。

### 3.3 LiDAR、轨迹与动态标签

顶置 LiDAR 数据用于获取道路和动态目标附近的稀疏三维测量。项目使用的相关字段包括 LiDAR timestamp、传感器 origin、ray direction、range，以及它们与 rig/world 坐标之间的变换关系。

NCore 同时提供：

- 离线 ego motion，即 `T_rig_world(t)`；
- 相机与 LiDAR 的离线内外参；
- cuboid labels，即动态对象的三维包围盒、类别、track ID 与时间关联；
- 场景中的相机/传感器 mask 等元数据。

这些数据共同支持将多路源观测对齐到同一个 NCore world 坐标系，并在目标 L4 相机位姿下重新观测重建场景。

## 4. 数据用途划分

### 4.1 静态背景训练

最终静态背景使用官方 2D Gaussian Splatting 训练。NCore 原始 FTheta 图像首先被重采样为多个 virtual-pinhole tile，并使用来源相机 pose 构成训练视图。

训练阶段使用：

- 5 路物理源相机的 RGB；
- NCore 相机标定、车辆 pose 与时间戳；
- 保守动态实例 mask，用于从静态 RGB 监督中排除动态目标区域；
- 原始 LiDAR 道路深度，用于道路尺度与表面深度约束；
- 经 LiDAR 尺度校准后的 Depth Anything V2 弱道路先验。

Depth Anything V2 是预训练单目深度模型，不是本项目新增采集数据；它只在有效静态道路区域提供低权重先验，真实 LiDAR 仍是主要物理深度约束。

### 4.2 天空资产构建

天空模块使用 7 路源相机、18 个时间采样和本地 SegFormer sky segmentation，构建世界方向 temporal cubemap。该资产只在静态 2DGS alpha 未覆盖的像素处补充天空颜色，不参与道路或动态目标的几何训练。

### 4.3 动态 actor 训练与选择

刚性车辆/作业设备的 actor expert 使用原始实例 mask、cuboid track、来源相机 RGB 与时间留出策略进行训练和筛选。每个 expert 都需要在来源相机的保留时间段中通过：

- mask 内 RGB MAE；
- alpha IoU；
- alpha 面积比；

等指标门槛。未通过门槛的动态对象不进入最终 registry。

行人和未能通过跨时间/跨相机验证的动态对象没有被作为可信 actor 写入 final 输出。

### 4.4 验证与评估

训练数据、验证数据和展示数据的角色如下：

| 类别         | 使用内容                                              | 作用                               |
| ------------ | ----------------------------------------------------- | ---------------------------------- |
| 静态训练     | 5 路来源相机、训练时间参考、静态区域 mask             | 优化 2DGS 静态表面                 |
| 静态验证     | 独立 proxy view、道路 LiDAR holdout                   | 计算 road-depth MAE、median、P90   |
| actor 验证   | 来源相机时间留出帧与实例 mask                         | 选择可靠 actor expert              |
| 合成安全审计 | 最终 1080p actor-composite RGB、actor alpha、静态 RGB | 验证 actor 外背景不被合成器污染    |
| 展示数据     | 7V MP4、mosaic、代表帧                                | 人工浏览与提交评审                 |
| 目标视角真值 | 当前无实采 target-L4 图像                             | 不用于训练、不用于像素级真实性评分 |

## 5. 最终提交样例与可追溯性

最终提交中的每个目标相机帧均可通过 `frame_mapping.csv` 追溯至：

- 目标相机 ID；
- 输出帧序号；
- 对应 NCore source reference frame；
- 对应时间戳；
- 目标小车 rig 配置；
- 静态 2DGS checkpoint；
- temporal sky 资产；
- actor expert registry。

提交包中的 `manifest.json`、`accepted_actor_registry.json`、`target_l4_rig.json`、道路 LiDAR holdout 报告和 SHA-256 校验表共同构成结果追溯证据。

## 6. 数据限制

1. 当前只使用一个 NCore clip 的一个 chunk，场景覆盖范围有限，不能代表所有道路、天气、城市形态和交通密度。
2. 静态 2DGS 主要恢复道路、建筑、树线、路沿和静态车辆背景；近场动态车辆、行人和遮挡表面仍可能出现模糊、静态泄漏或缺失。
3. 目标 L4 相机为工程定义的 rectified pinhole rig，不包含目标实车 OEM 标定、镜头畸变、曝光响应、ISP 或 rolling shutter。
4. 最终 7V 输出没有对应的目标小车实采 RGB 真值，因此动态对象和跨相机新视角质量只能通过来源视图留出、几何约束与合成安全代理进行评估。
5. 不同时间、不同来源相机对同一动态对象的观测可能不完整；本项目采用 fail-closed gate，宁可回退静态背景，也不强行生成缺乏验证的动态表面。
